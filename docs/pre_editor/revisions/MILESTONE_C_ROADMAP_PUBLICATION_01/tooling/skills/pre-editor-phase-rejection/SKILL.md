# PRE_EDITOR phase rejection

Use only for an explicit `REJECT PRE_EDITOR PHASE XX` instruction for phase 00-58.
Quoted commands and general praise select no action. Reuse current AGENTS
instructions; load only current ownership evidence, not every phase or mode skill.
The standing publication grant is not activated by rejection.

Read `docs/pre_editor/active/REFACTOR_STATE.md`, the current
`docs/pre_editor/active/PHASE_XX_REVIEW.md`, current checkpoint spec and recorded
phase-entry ownership. Read the named `pre-editor-checkpoints/phase-XX.json` and
private journal if present. Before SEAL, a candidate may have only its automated
handoff and no receipt/journal; do not create either to reject it. Use only the
PRE_EDITOR journal namespace under this worktree's Git directory.

Only explicit REJECT requests rollback; ordinary findings request revision.
If a commit/tag or approval transaction exists, preserve it and stop for a
separately authorized recovery/correction. Rejection never rewrites history.

For an unapproved candidate, compare current files with entry and sealed hashes,
or the immutable automated-handoff hashes when no current seal exists. Missing
ownership evidence never authorizes destructive restoration; preserve and report.
Restore only exact phase-owned tracked changes to their recorded clean baseline.
Remove a newly created file only when entry proves absence and current content
contains no owner changes. Preserve mixed/changed files and report the overlap
when safe isolation is unavailable. Preserve index entries and later RBS edits.
Use original byte copies for pre-existing local files, never guessed content.
If present, retire only this worktree's unstarted phase journal after successful
selective restoration; retain durable blob refs and needed rejection evidence. Do not run
broad reset/clean/restore. Check protected hashes/index, leave this phase as the
next expected phase, report complete or partial rejection, and stop.
